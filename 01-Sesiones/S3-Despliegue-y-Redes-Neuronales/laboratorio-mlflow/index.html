A · La idea

Sin MLflow: «¿qué modelo era el bueno?»

Sin seguimiento

  • Entrenas tres modelos; el AUC queda en el terminal y se pierde.
  • Una semana después nadie sabe con qué datos se entrenó el que está en la API.
  • El archivo modelo.joblib se sobrescribe: no hay vuelta atrás.

Con MLflow (lo hace train.py)

  • Seguimiento: cada entrenamiento deja una ejecución con parámetros (lo decidido antes) y métricas (lo medido después).
  • La huella_datos en cada ejecución: con qué datos exactos se entrenó.
  • Registro: el elegido se guarda como retencion-90d y cada entrenamiento crea una versión nueva; las anteriores no se borran.
  • La firma viaja con el modelo: la API comprueba con ella su contrato (S2).

A · El mapa

Dos piezas: seguimiento y registro

Parámetros (train.py)

modelo, ventana_objetivo_dias, n_variables, huella_datos.

Métricas: partición_métrica

train_ / valid_ / test_ + auc, precision_media, tasa_base, aciertos_en_el_10_mejor: 12 por ejecución.

Etiquetas de cada versión

modelo, huella_datos y valid_auc.

B · Dónde lo guarda el proyecto

Dos sitios en models/, y una ruta absoluta

Por qué python -m ia_mlops.mlflow_ui

  • mlflow ui --backend-store-uri sqlite:///models/mlflow.db usa una ruta relativa: lanzado desde la raíz del repositorio, crea otra base vacía sin avisar.
  • mlflow_ui calcula la ruta absoluta (config.MODELOS), comprueba que hay ejecuciones y solo entonces arranca la web.
  • Es la misma base en la que escribe train.py.

Ni hay que crearla ni se edita a mano

  • La crea el primer entrenamiento con MLflow (python -m ia_mlops.pipeline).
  • La web lee la base cada vez: tras entrenar basta con F5.
  • Empezar de cero: borrar models/mlflow.db y models/mlartifacts/, los dos.

C · Paso 11 · terminal T2

Del registro a una predicción, desde Python

T2 · pega la orden entera (de python a EOF)
python - <<'EOF'
import json, warnings
warnings.filterwarnings('ignore')
import mlflow, mlflow.sklearn
import pandas as pd
from ia_mlops import config, mlflow_ui

mlflow.set_tracking_uri(mlflow_ui.uri())          # la base DEL PROYECTO, con ruta absoluta
nombre = config.MODELO_REGISTRADO                 # 'retencion-90d'
versiones = mlflow.MlflowClient().search_model_versions(f"name='{nombre}'")
ultima = max(int(v.version) for v in versiones)
print(f'Modelo registrado {nombre}: versiones {sorted(int(v.version) for v in versiones)}; cargo la {ultima}')

uri = f'models:/{nombre}/{ultima}'
firma = mlflow.models.get_model_info(uri).signature
print('Firma:', len(firma.inputs.inputs), 'entradas ->', firma.outputs.inputs[0].type)

modelo = mlflow.sklearn.load_model(uri)
cliente = json.load(open('tests/datos/cliente_ejemplo.json'))
fila = pd.DataFrame([cliente])[config.FEATURES]
print(f'Probabilidad de recompra en 90 días (cliente de ejemplo): {modelo.predict_proba(fila)[0, 1]:.3f}')
EOF

D · Hacia S4 y S5

En producción: qué versión está sirviendo

Trazabilidad

Cada versión apunta a su ejecución: parámetros, métricas y huella de los datos. Ante una predicción rara se sabe qué modelo fue.

Alias (S4 y S5)

Se pone un alias, por ejemplo produccion, a una versión. El despliegue carga el alias, no un número fijo.

Vuelta atrás

Si la versión nueva falla, se mueve el alias a la anterior. No se reentrena ni se borra nada.

Hoy la API carga la carpeta models/modelo_mlflow; en S4 y S5 se desplegará una versión concreta del registro.

Cierre

Cuatro preguntas para llevarte

1. ¿Qué diferencia hay entre un parámetro y una métrica?

Ver la respuesta

El parámetro se decide antes de entrenar (modelo, n_variables…); la métrica se mide después (valid_auc…).

2. ¿Por qué python -m ia_mlops.mlflow_ui y no mlflow ui a pelo?

Ver la respuesta

Porque calcula la ruta absoluta de models/mlflow.db; con la relativa, desde otra carpeta, MLflow crea una base vacía sin avisar.

3. ¿Por qué sin --forzar no se creó la versión 2?

Ver la respuesta

El pipeline es idempotente: mismos datos y mismo código → «sin cambios», no entrena.

4. ¿Qué es la firma y quién la usa?

Ver la respuesta

El contrato de entrada y salida del modelo (13 entradas, 1 salida). La API la comprueba al arrancar.
