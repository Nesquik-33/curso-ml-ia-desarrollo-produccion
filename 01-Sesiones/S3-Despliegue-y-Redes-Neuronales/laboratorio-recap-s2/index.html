Siglas de hoy

SiglaQué es
APIInterfaz de programación: el modelo atiende peticiones HTTP (Protocolo de Transferencia de Hipertexto) con JSON.
FSCapa de variables (*feature store*): las 13 variables de cada cliente en una fecha de corte.
UIInterfaz de usuario: la página web de consulta.
JSONNotación de objetos de JavaScript: el formato de texto de las peticiones.
SQLLenguaje de consulta estructurado: el que calcula las variables.

Lo que vamos a recorrer

Del id a la recomendación, en cinco piezas

La API no sabe qué es un id

Pide las 13 variables del contrato y devuelve una probabilidad. No lee datos de clientes.

La persona no conoce las variables

Solo tiene el id del cliente y quiere saber qué hacer con él.

La interfaz hace de puente

Calcula las variables con el mismo SQL de FS que al entrenar, llama a la API y aplica la regla de tramos.

C · La idea

La capa FS guarda cortes del pasado; la campaña es hoy

Lo que hay en la base

La tabla fs_cliente_corte tiene las variables de cada cliente en los 10 cortes de entrenamiento, validación y prueba (de 2010-06-01 a 2011-09-01).

Lo que pide la campaña

El corte de hoy del dato: el día siguiente a la última factura, 2011-12-10. No está guardado: hay que calcularlo.

Cómo se calcula: explotacion.variables_en_corte

  • Ejecuta el mismo SQL de la capa FS: sql/fs/02_poblar_fs.sql.
  • Escribe en una tabla temporal: la capa FS del proyecto no se toca.
  • Regla de oro: solo datos anteriores al corte (fecha_factura < :corte).
  • Lo usan la interfaz y python -m ia_mlops.explotacion.
Mismo cálculo al entrenar y al predecir: si no, el modelo recibiría variables distintas de las que aprendió.

C · Paso 8 · terminal T3 (no necesita la API)

Las variables del 13599, en dos cortes

T3 · pega la orden entera (de python a EOF)
python - <<'EOF'
import pandas as pd
from ia_mlops import config, db, explotacion as ex
con = db.conectar(); cid = 13599; t = {}
for corte in ['2010-12-01', ex.corte_por_defecto(con)]:
    v = ex.variables_en_corte(con, corte)
    t[f'al vuelo {corte}'] = v.loc[v.cliente_id == cid, config.FEATURES].iloc[0]
fs = pd.read_sql("SELECT * FROM fs_cliente_corte WHERE cliente_id = ? AND fecha_corte = '2010-12-01'", con, params=[cid])
t['tabla fs 2010-12-01'] = fs[config.FEATURES].iloc[0]
t = pd.DataFrame(t); print(t.to_string())
a, b = t.iloc[:, 0], t.iloc[:, 2]
print('Iguales en el corte entrenado:', bool(((a == b) | (a.isna() & b.isna())).all()))
print('Cortes guardados en fs_cliente_corte:', [r[0] for r in con.execute('SELECT DISTINCT fecha_corte FROM fs_cliente_corte ORDER BY 1')])
EOF

Si falla

  • No existe la capa FS: falta el pipeline (paso 1).
  • ModuleNotFoundError: ia_mlops: no estás en 04-Proyecto-Base.
  • Se queda esperando con >: no se copió la última línea, EOF. Escríbela y pulsa Intro.

Cierre

Cuatro preguntas para llevarte

1. ¿Por qué la API pide variables y no un id?

Ver la respuesta

Para que la imagen del modelo no lleve datos de clientes: el dato lo pone la interfaz.

2. ¿Qué garantiza que las variables de hoy sean «como las de entrenar»?

Ver la respuesta

El mismo SQL de FS (02_poblar_fs.sql); en el corte entrenado, el cálculo al vuelo da los mismos valores que la tabla.

3. ¿Qué significa «revisar» en el 13599?

Ver la respuesta

Una variable (antigüedad 738) está fuera de lo visto al entrenar (1 a 364): la probabilidad no tiene respaldo ahí.

4. API parada: ¿qué dan /salud y /listo de la interfaz?

Ver la respuesta

/salud 200 (vivo) y /listo 503 con el motivo (no lista).
